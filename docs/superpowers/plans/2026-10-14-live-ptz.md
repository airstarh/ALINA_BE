# Live PTZ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add safe, capability-gated PTZ movement, zoom, and numeric preset management beside the existing live Balcon stream.

**Architecture:** A focused ONVIF client performs one bounded `ContinuousMove` pulse with an unconditional `Stop`; the existing DVRIP client performs vendor preset actions. `CameraService` validates live capabilities and commands, the JSON API exposes read/POST routes, and the Live renderer owns pointer-hold behavior without overlapping requests.

**Tech Stack:** PHP 8.2, DVRIP, ONVIF SOAP, browser ES modules, Node test runner.

**Spec:** `server/var/www/zero.home/addon/cam/ai/docs/2026-10-14-live-ptz-design.md`

## Global Constraints

- Do not move any physical camera from automated tests.
- Directions describe physical axes and are not reversed for Mirror or Flip.
- Every movement request is a bounded pulse whose `Stop` runs even after a movement error.
- Door and cameras without `SupportPTZDirectionControl=true` receive no actionable controls.
- Preset save/delete require confirmation; preset recall does not.
- Do not claim to enumerate saved preset slots.
- Do not commit or run a JavaScript SPA build.

## Review Focus

- Forged direction, speed, duration, or preset values must be rejected before an I/O call.
- A `ContinuousMove` failure must still attempt `Stop`; a `Stop` failure must disable further UI movement.
- Pointer release, cancellation, blur, visibility loss, and view destruction must end the repeat loop.
- Slow responses must never overlap or queue stale pulses.
- A camera with generic ONVIF PTZ data but no DVRIP motor capability flag must remain non-actionable.
